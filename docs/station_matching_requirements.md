# 地铁站点识别与匹配需求文档

## 1. 背景

当前 OCR 系统对地铁车厢红色导航条的文字识别不稳定，同一帧在不同次识别中结果不一致（如"当前站：轨道大厦"有时识别为"百前站：轨道大厦"、"轨道大厦"等）。需要通过已知站点列表做模糊匹配来纠正识别结果，提高输出稳定性。

## 2. 功能概述

- 维护一份地铁站点名称列表（JSON 文件）
- OCR 识别后，通过锚点字判断前缀（"当前站" / "下一站"）
- 提取站名部分，与站点列表做模糊匹配，纠正识别错误
- 匹配成功且文本变化时才输出结果

## 3. 站点列表管理

### 3.1 文件位置

```
config/stations.json
```

### 3.2 文件格式

平铺列表，按线路分组便于维护：

```json
{
  "金义东线": [
    "轨道大厦",
    "金华南站",
    "高铁新城",
    "大堰河街"
  ],
  "其他线路": [
    "站名A",
    "站名B"
  ]
}
```

程序启动时加载所有线路的站名到一个扁平列表中。

### 3.3 站点列表要求

- 只包含中文站名（不含"当前站"、"下一站"等前缀）
- 不含英文站名
- 站名以实际为准，如"轨道大厦"而非"轨道大厦站"

## 4. 前缀识别

### 4.1 已知前缀

| 前缀 | 锚点字 |
|------|--------|
| 当前站 | "当" 或 "前" |
| 下一站 | "下" 或 "一" |

### 4.2 识别规则

1. 从 OCR 文本中提取前缀部分（冒号前的内容）
2. 检查是否包含锚点字：
   - 包含"当"或"前" → 前缀为"当前站"
   - 包含"下"或"一" → 前缀为"下一站"
3. 都不包含 → 前缀识别失败，跳过不输出

### 4.3 示例

| OCR 原始文本 | 前缀判断结果 |
|-------------|-------------|
| "当前站：轨道大厦" | "当前站" ✓ |
| "百前站：轨道大厦" | "当前站" ✓（"前"命中） |
| "自前站：金华南站" | "当前站" ✓（"前"命中） |
| "下一站：大堰河街" | "下一站" ✓ |
| "一站：金华南站" | "下一站" ✓（"一"命中） |
| "站：金华南站" | 识别失败 ✗（无锚点字） |
| "轨道大厦" | 识别失败 ✗（无锚点字） |

## 5. 站名匹配

### 5.1 匹配流程

1. 从前缀识别后的文本中提取站名部分（去掉前缀和标点）
2. 按以下优先级匹配站点列表：
   - **精确匹配**：站名完全一致 → 命中
   - **前缀包含**：OCR 站名是列表中某站名的前缀（如"轨道"匹配"轨道大厦"）→ 命中
   - **后缀包含**：列表中某站名是 OCR 站名的前缀（如"轨道大厦站"包含"轨道大厦"）→ 命中
   - **模糊匹配**：字符重叠率 > 0.6 → 命中（使用 difflib.SequenceMatcher）
3. 匹配失败 → 不输出

### 5.2 匹配示例

| OCR 站名部分 | 匹配方式 | 匹配结果 |
|-------------|---------|---------|
| "轨道大厦" | 精确 | "轨道大厦" |
| "轨道" | 前缀包含 | "轨道大厦" |
| "金华南站站" | 后缀包含 | "金华南站" |
| "轨道大厦站" | 后缀包含 | "轨道大厦" |
| "大堰河" | 模糊 | "大堰河街" |
| "随机文字" | 无匹配 | 不输出 |

## 6. 输出规则

### 6.1 输出条件

同时满足以下条件才输出：
1. 前缀识别成功（有锚点字）
2. 站名匹配成功（命中站点列表）
3. 文本与上一次输出不同（变化检测）

### 6.2 输出格式

```
当前站：轨道大厦
下一站：金华南站
```

### 6.3 不输出的情况

- 前缀识别失败（无锚点字）
- 站名匹配失败（不在站点列表中）
- 文本与上次相同（未变化）
- ROI 检测失败（未找到红色条）

## 7. 检测频率

- 数据流/视频模式：每秒检测 1 次（frame_interval=30，30fps 流）
- 图片模式：单次检测
